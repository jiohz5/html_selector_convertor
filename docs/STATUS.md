# 현황 정리 — 2026-10-07

HTML Previewer(① 디자인 고르기)와 html-convertor(② 데이터 → HTML)를 한 프로젝트로 합쳤고, 브라우저만으로 쓰는 단일 HTML 버전까지 만들었다.
흐름 분석에서 **입력 형식 · 선택 연동 · 계산 정확도** 문제가 확인되어 아래 4장에 정리했다. 2026-10-07부터 HTML 입력을 우선 개선하며, 이후 안정화 작업은 [순차 계획](superpowers/plans/2026-10-07-convertor-stabilization.md)을 따른다.

### 2026-10-07 HTML 우선 업데이트

- `.html`·`.htm`의 정적 표와 우리 출력의 내장 `hc-spec`을 지원한다. 여러 표는 선택하며 `<tfoot>`은 집계하지 않는다.
- 입력 형식 등록 목록에서 판별·파일 선택창·화면 안내를 관리한다. 등록되지 않은 확장자는 CSV로 읽지 않고 오류를 표시한다.
- 입력을 시작하거나 실패하면 이전 결과·미리보기·다운로드를 제거한다. 늦게 끝난 이전 파일 읽기는 현재 결과를 덮어쓰지 않는다.
- 일반 HTML의 본문·디자인 전체 변환, 병합·중첩 표, 여러 줄 머리글은 후속 범위다. 아래 P1·P2는 관련 부분을 개선했으며 전체 안정화 회귀는 Task 0·1에서 확장한다.
- 형식 추가와 원본 사이트 종료 시 지원 방안: [MAINTENANCE.md](MAINTENANCE.md).
- 로컬 검증: 폴더판·단일판 HTML 입력 27개 기능 그룹, 기존 make 흐름(엑셀·CSV·다운로드·spec·모바일), 렌더러 비교 54/54, 정적 검사 48/48 통과. 문자열 요약·빈 영역·meta 전용 기존 spec의 복원과 손상 spec 거부도 포함한다.

### 원문 텍스트 입력

- 파일 업로드가 어려울 때 ② 데이터 패널의 "원문 텍스트로 입력"을 펼쳐 붙여 넣을 수 있다.
- 형식은 자동 감지 또는 CSV(.csv)·TSV(.tsv)·TXT(.txt)·JSON(.json)·HTML(.html)·HTM(.htm)으로 지정한다. 선택 목록은 reader의 텍스트 지원 정보에서 생성한다.
- 자동 감지는 `{`·`[` 시작을 JSON, `<` 시작을 HTML, 일관된 구분표를 CSV·TSV로 판별한다. 애매한 본문은 수동 형식 선택을 요청하고, 손상된 JSON·HTML을 CSV로 다시 읽지 않는다.
- 엑셀 바이너리 원문은 지원하지 않으며 엑셀에서 복사한 셀의 TSV·CSV는 입력할 수 있다.
- 파일 입력과 같은 reader·profile·spec·render 경로를 사용한다. 실패해도 입력 본문은 유지하고 이전 결과·미리보기·다운로드는 제거한다. HTML 원본 스크립트는 비활성 상태로 읽으며 사내·외부 모델 연계는 없다.
- 빈 첫 TSV 머리글·마지막 빈 TSV 열과 따옴표 안의 구분자·줄바꿈이 있는 CSV 머리글을 보존한다. CSV 구분자 수정은 파일 입력에도 적용한다.
- 로컬 검증: 폴더판·단일판 원문 입력 32개 기능 그룹씩 통과. 자동·수동 형식, 오류 후 본문 유지와 결과 제거, HTML spec·다중 표, 파일/텍스트 읽기 경쟁, 모바일 화면, 실제 CSV 파일 선택을 포함한다. 수정 후 기존 HTML 입력 27개 기능 그룹도 통과했다.

### HTML 내장 JSON 레코드 읽기

- HTML의 정적 표와 인라인 `script[type="application/json"]` 레코드를 같은 데이터 선택 목록에 넣는다. 표 머리글만 있고 본문을 원본 JavaScript로 채우는 HTML도 내장 JSON 레코드가 있으면 읽을 수 있다.
- `hc-spec`이 있으면 먼저 검증하여 복원하고, 손상 spec은 오류로 처리한다. spec이 없으면 첫 유효 정적 표를 기본 선택하며 정적 표가 모두 읽기 불가일 때 첫 유효 JSON을 선택한다. JSON 선택 항목은 script ID·JSON 경로·행 수를 표시한다.
- JSON 객체 경로를 탐색하다 배열을 만나면 그 아래를 더 탐색하지 않는다. 모든 행이 null이 아닌 객체인 배열만 표로 바꾸며 열은 전체 행의 키를 합친다. 레코드 셀의 객체·배열은 JSON 문자열로 보존한다.
- 속성의 스칼라 배열은 제외하고, 빈·혼합·null 행이 있는 레코드 후보는 사용 불가 사유를 표시한다. JSON-LD·일반 JavaScript·외부 `src`는 실행하거나 읽어 오지 않는다. 이 경로 탐색은 HTML 내장 JSON의 지원 범위이며 일반 JSON 파일의 중첩 입력 지원과는 별도다.
- 원본 레코드를 읽어 현재 디자인으로 다시 만드는 기능이다. 원본 페이지의 계산·집계·입체 SVG·조작 기능을 재현하거나 원본 JavaScript의 계산을 실행하는 기능은 포함하지 않는다.
- 로컬 검증: 폴더판·단일판 내장 JSON 회귀 16개 기능 그룹씩 통과. 특수 필드 이름과 누락 칸, 501번째 행에서 등장한 열도 보존한다. 실제 첨부는 파일·자동 감지·HTML 지정 원문 입력으로 두 데이터 목록을 확인했다. 기존 HTML 27개·텍스트 32개 그룹은 두 배포판에서 통과했고, 엑셀·CSV·다운로드·spec·모바일 make 흐름도 통과했다.

## 4. 검증된 문제

아래는 2026-10-06 분석 당시의 문제 기록이다. P1·P3(일부)·P5 확인, 나머지는 대부분 맞고 일부를 바로잡았다. 줄 번호는 분석 당시 기준이며 후속 개선은 각 항목에 날짜로 표시한다.

### 🔴 P1. 지원하지 않는 입력을 오류 없이 잘못 읽는다
2026-10-07: 브라우저는 등록된 확장자만 읽고 HTML 표·내장 JSON 레코드·내장 spec을 지원한다. MD·PDF 등은 명시적으로 거부한다. Python 스크립트와 선택 내보내기 분류는 남은 작업이다.

- `assets/convertor.js` readFile(:124-143)의 분기는 엑셀(:128) · JSON(:134) · 그 밖(:140 CSV)뿐이다. 구분자는 첫 줄로 정한다(detectDelimiter :57-66).
- 끌어다 놓기(:897)와 ingest(:788-810)에 확장자 검사가 없다. 제한은 `index.html`:151 `accept`뿐이다.
- MD·HTML·PDF·DOCX·이미지·① 내보내기가 모두 "표"로 처리되고 HTML 다운로드까지 활성화된다. `check_html.py`는 구조만 보므로 이 결과물도 통과시킨다.
- 스킬 `profile_data.py`(:47-51)도 확장자 허용 목록 없이 `read_csv(sep=None)`으로 읽어 MD 표·HTML을 엉뚱한 열로 낸다(exit 0).

### 🔴 P2. 읽기에 실패해도 직전 결과가 남아 그대로 다운로드된다
2026-10-07: 브라우저 업로드 시작·실패·렌더링 실패 시 이전 결과를 제거하며, 일반 업로드와 spec 업로드가 같은 입력 세대 검사를 사용한다. 전체 상태 회귀와 오류 문구 정리는 Task 1에서 이어간다.

- 오류 처리(:806-809)는 오류 표시와 상태줄 비우기만 한다. 직전 파일의 미리보기·열 패널·켜진 다운로드 버튼(:751에서 켜고 끄는 곳 없음)이 남는다.

- 중첩 JSON의 오류 문구(:117)는 "spec.json 불러오기"를 안내하지만, 그 버튼도 같은 isSpec(:107-109)을 요구해 해결이 안 된다.

### 🔴 P3. ① 선택이 ②로 이어지다 끊긴다
- ②에서 디자인을 한 번 직접 고르면(드롭다운 :935, 칩 :946, 모달 "이 디자인으로 만들기" :992) `designChosen=true`가 저장되고, 되돌리는 코드가 없다. 이후 applySelection(:675)이 ① 선택을 무시하는데, 화면에 안내가 없다.

- ①에서 차트를 빼거나 선택을 비워도 ②의 차트·디자인 값은 남는다(:675-679).

### 🟠 P4. 규칙 기반 계산이 흔한 데이터에서 틀리거나 오해를 부르는 숫자를 낸다
- 일부 기간 판정 문턱이 "이전 기간 날짜 수 중앙값의 70%"(:385-391)다. 그래서 22일치 9월도 완결된 달로 보고 단순 합계를 비교한다. 일평균이 같아도 "▼29%"가 나온다.
- "합계·소계" 행을 거르지 않아 이중으로 집계된다(:338-345, :462-465). 합계 행이 든 표에서는 총합이 두 배가 되고, 도넛에서 "합계"가 50%를 차지한다.
- 첫 행을 무조건 머리글로 쓴다(CSV :140-142, 엑셀 :145-148). 제목 행이 있으면 열 이름이 틀리고, 데이터가 9행 이하이면 "건수" 대시보드가 된다.
- % 증감을 소수 1자리로 먼저 반올림해(:431) 작은 변화 보정(:433)에 도달하지 못한다. 실제 엑셀의 +0.032%가 "0%"로 표시된다.
- 엑셀 라이브러리 공식 CDN이 막혀 대체 CDN의 SheetJS 0.18.5가 쓰이면, 한국 시간대에서 날짜 셀이 하루씩, 월 데이터가 한 달씩 밀린다(:14-17, :130, :101).
- 그 밖: 주 단위 데이터라도 기간이 짧으면 시간 단위가 "일"로 잡혀 차트 제목(일별)과 KPI(주)가 어긋난다.

### 🟠 P5. 스킬 스크립트의 입력 처리
- `profile_data.py`: 한 겹 감싼 JSON·중첩 JSON·spec.json을 `pd.read_json`이 dict/list 칸으로 읽어 nunique(:80)에서 TypeError가 난다. 호출(:160)이 try(:154-158) 밖에 있어 traceback으로 끝나고, 여러 파일을 함께 넘기면 정상 파일 결과까지 출력되지 않는다.
- `resolve_design.py`
  - 여러 줄 메모는 첫 줄만 읽는다(:68).
  - BOM이 붙은 JSON 내보내기는 자유 텍스트 매칭으로 넘어가 고르지 않은 디자인을 고른다.
  - 인자 없이 실행하면 가장 최근 내보내기 파일을 확인 없이 쓴다(:39-44).

### 🟡 P6. ApexCharts 라이선스 안내 정정
- 결과물이 불러오는 버전은 `designs.json`에 고정된 **apexcharts@4.7.0이고, 이 버전은 MIT**다(배포 파일 머리말, npm 확인).
- "연매출·예산 200만 달러 이상 조직은 상용 라이선스 필요"인 듀얼 라이선스는 **5.3.0(2025-07-21)부터** 적용된다(5.0.0은 MIT, 최신 7.8.0은 듀얼).

| 버전 | 배포일 | 라이선스 |
|---|---|---|
| 4.7.0 (결과물이 쓰는 버전) | 2025-04-24 | MIT |
| 5.0.0 | 2025-07-09 | MIT |
| 5.3.0 | 2025-07-21 | ApexCharts License (듀얼) |

- 그래서 ② 화면의 경고(`assets/hc-render.js`:213-214, "ECharts로 바꾸기" 버튼 `assets/convertor.js`:739-741)는 현재 결과물 기준으로 지나치다. Previewer의 ApexCharts 카드 설명(최신 버전 기준)도 버전 구분이 필요하다. README는 이번에 바로잡았다.
- 스킬 경로는 반대로 아무 안내가 없다. `resolve_design.py`의 notes(:145-154)는 고른 항목만 검사하고, 기본값으로 정해진 차트 라이브러리(:143)는 보지 않는다.
- 실제 위험은 CDN 버전을 5.3 이상으로 올릴 때 생긴다. 기본값을 ECharts로 바꿀 필요는 없다.
